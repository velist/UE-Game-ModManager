# 爱酱 MOD 管理器 · 故障排查

适用版本：2.1.2 · 更新日期：2026-10-23

## 无法启动

1. 确认已安装 **.NET 8 Desktop Runtime（x64）**。本包没有内置运行时；仅安装 ASP.NET Runtime 或 x86 运行时不能满足要求。
2. 查看错误对话框，以及 `%LOCALAPPDATA%\UEModManager\Logs\` 中的日志。旧版日志可能位于程序目录。
3. 确认没有另一份管理器仍在运行。如果持续无法启动，关闭程序后备份本机和漫游数据目录，再反馈错误信息。

不要把直接删除数据库、WAL 文件或整个用户目录作为常规排障步骤。

## MOD 导入后看不到或未生效

- 确认当前选择了正确的游戏，清除搜索文字和分类筛选；列表上方的类型切换应选“全部”。
- RAR / 7Z 压缩包需先用 WinRAR 或 7-Zip 解压，再导入解压后的文件夹或文件。
- 导入确认里默认未勾选的文件，是被识别为游戏原版文件的（如 `pakchunk0-Windows.pak`、`pakchunk26-Windows_P.pak`）；确认是 MOD 时手动勾上再导入。单独拖入的说明、图片、网页文件会被跳过。
- 核对 MOD 是否已经启用，并检查部署操作是否成功。
- 核对游戏路径、MOD 部署位置，以及 UTOC / UCAS 等配套文件是否齐全。
- 查看卡片上的红色冲突数字，用“冲突检测”逐组处理，并确认 MOD 支持当前游戏版本。
- 游戏运行时先关闭游戏，再变更 MOD。

## 路径、权限或磁盘空间错误

检查程序提示的实际路径。仓库盘、游戏盘和备份盘都可能需要可用空间，不要只检查程序安装盘。程序以复制方式部署，仓库与游戏可以不在同一个盘。权限不足时，可在错误提示里点“以管理员身份重启”。

2.1.1 及更早版本在设置页点“保存设置”可能误报仓库迁移失败，2.1.2 已修复。

如果遇到文件占用，先关闭游戏或正在访问对应文件的程序。不要直接删除仍被方案引用的包、事务记录或部署备份。

## 部署中断或出现恢复提示

保留当时的错误信息，按恢复窗口提供的操作处理。切换方案时部署失败会自动留在原方案并恢复游戏文件，可稍后重试。恢复失败时，先备份现有配置、仓库和事务备份，再导出诊断信息。不要反复强制启停同一个 MOD 来掩盖未完成的恢复。

## 游戏更新后无法禁用或删除 MOD

游戏更新改写了 MOD 已装入的文件时，会提示“文件已被游戏更新”。选“交给游戏（推荐）”：这些文件按游戏当前版本保留、不再由管理器管理，MOD 其余部分照常处理。

## 登录或验证码问题

程序启动时不会弹出登录窗口，账号入口在左侧边栏底部。核对邮箱、垃圾邮件箱和网络连接，稍后重试。账号服务异常时仍可使用无需登录的本地 MOD 管理功能。账号登录不会自动从云端恢复 MOD 文件。

## 升级后找不到旧数据

新版数据分布在：

- `%LOCALAPPDATA%\UEModManager\`
- `%APPDATA%\UEModManager\`
- 设置中指定的 MOD 仓库、生成物与备份目录

旧版还可能在原程序目录留下 `Data\`、`UserData\` 或 `config.json`。先保留原文件，再使用随包迁移工具或联系作者。迁移工具主要备份配置与索引，大型仓库和备份目录需另行复制。

## 收不到新版本提示

启动后程序会查询一次最新版本号，与统计开关无关。收不到提示通常是网络无法访问官网（代理、防火墙），可关注官网与群公告。

## 如何反馈

在“设置 → 反馈与诊断”或“存储与恢复”中导出诊断包，并记录：

- 软件版本、游戏名称和复现步骤；
- 期望结果与实际结果；
- 完整错误文字，必要时附截图。

诊断包有脱敏处理，发送前仍请检查包内内容。
